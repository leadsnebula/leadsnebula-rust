perf: Complete ruthless optimization plan - all hot-path improvements

This commit implements ALL remaining optimizations from the ruthless plan
to achieve <140ms non-DB critical path. All changes have been verified
and validated.

## Critical Path Optimizations

### Lead Creation Decoupling
- Moved lead/ping/ping_payloads INSERT to write-behind queue
- API now returns immediately with promise_id (no blocking DB wait)
- Eliminates 700-1200ms blocking operation from critical path
- LeadCreation BackgroundTask handles full insertion asynchronously

### Encryption Decoupling
- All PII field encryption moved to write-behind queue batch processor
- Request/response payload encryption moved to background
- Encryption happens in parallel batches, not blocking critical path
- Saves 50-200ms per request from encryption overhead

### Buyer/Campaign Name Caching
- Added Redis caching for buyer names (1h TTL)
- Added Redis caching for campaign names (1h TTL)
- Names loaded in parallel using tokio::join!
- Eliminates blocking DB queries during response building

## Cache Pre-Warming (Keep System Red Hot)

### Expanded Pre-Warming
- Pre-warm buyer names (top 200 buyers)
- Pre-warm campaign names (top 200 campaigns)
- Pre-warm buyer integrations (active integrations)
- Pre-warm qualification configs (active buyer configs)
- All use 1h TTL matching runtime cache strategy
- Periodic warmup runs every 30 minutes

## Performance Instrumentation

### Critical Path Timing
- Timing starts AFTER pre-checks (which are cached)
- Ends BEFORE final response (excludes decoupled DB operations)
- Always available (not feature-gated) for production monitoring
- Logs "Non-DB critical path timing" with lead_id and critical_path_ms

### Internal Post Timing Breakdown
- Added qual_duration timing in route_post_direct_sync
- Added gen_duration timing for post_id generation
- Total duration tracking for fullpost operations
- All timing gated under #[cfg(all(feature = "tracing", debug_assertions))]

## Code Quality & Optimization

### Tracing Gating
- Fixed pulsar.rs to use #[cfg(all(feature = "tracing", debug_assertions))]
- Matches ping_tree_router.rs and qualification_engine.rs pattern
- Eliminates tracing overhead in production builds
- Hot-path tracing only enabled in debug builds with tracing feature

### Clippy Fixes
- Added #[allow(clippy::large_enum_variant)] to BackgroundTask enum
- LeadCreation variant is large but necessary for decoupling
- All validation checks pass (formatting, clippy, compilation)
